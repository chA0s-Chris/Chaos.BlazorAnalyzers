# KOS8001 — Member is assigned in a Blazor lifecycle method

| Item                  | Value                                    |
|-----------------------|------------------------------------------|
| Suppressed diagnostic | `CS8618`                                 |
| Suppressor            | `BlazorLifecycleNullabilitySuppressor`   |
| Enabled by default    | Yes                                      |

## Cause

A non-nullable field or property of a component deriving from `ComponentBase` is assigned in
`OnInitialized` or `OnInitializedAsync`, and the compiler reports `CS8618` because the member is not
assigned by the time the constructor exits.

## Why the warning is a false positive

`CS8618` is a statement about constructor exit. Blazor constructs a component and then runs its
lifecycle methods before the component renders or is otherwise observable, so a member assigned in
`OnInitialized`/`OnInitializedAsync` is non-null everywhere the developer can actually reach it.

```csharp
public partial class Weather : ComponentBase
{
    private Forecast[] _forecasts;   // CS8618 without this suppression

    protected override async Task OnInitializedAsync()
        => _forecasts = await Client.GetForecastsAsync();
}
```

Both `Member = value` and `this.Member = value` are recognised, anywhere inside the method body
including nested blocks. The scan covers **all** partial declarations of the type, so the usual
`.razor` plus `.razor.cs` split works.

## Limitations

These are known and deliberate; the rule favours a simple, predictable signal over deep analysis.

- **Assignments are matched by name, not by symbol.** A local variable that shadows the member name
  and is assigned in a lifecycle method suppresses the warning:
  ```csharp
  protected override void OnInitialized()
  {
      string Member;        // shadows the member
      Member = "local";     // still counts as an assignment to the member
  }
  ```
- **Only `OnInitialized` and `OnInitializedAsync` count.** A member assigned in `OnParametersSet`,
  `OnParametersSetAsync`, `SetParametersAsync`, or `OnAfterRender` is not suppressed.
- **The method is matched by name, not verified as an override.** A private helper that happens to
  be called `OnInitialized` is treated as a lifecycle method.
- **Assignments inside lambdas and local functions count**, even when that code never runs
  synchronously.

Weigh the last three against [KOS8002](KOS8002.md), which is backed by a real framework guarantee.

## How to turn it off

```ini
dotnet_diagnostic.KOS8001.severity = none
```

`CS8618` is then reported again for these members. Consider `required` or a nullable declaration as
the alternative.
